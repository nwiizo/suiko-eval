# 推敲後の意味と声の確認（2026-10-30）

Suikoの同梱Skillとホーム配置版を使い、自作の3原稿について修正文を保存した。
`inputs/`が原文と提供資料、`suiko/`と`home-suiko/`が各Skillによる実際の出力である。
特定の言い換えとの文字列一致ではなく、次の基準で本文を確認した。

1. 主体・相手・対象、許可・能力・義務、条件・否定・確度・数量を保つ。
2. 見出しと重要な内容を落とさず、資料にない事実を足さない。
3. 主述のねじれ、不自然な名詞化、不要な読点、補助動詞表記を直す。
4. 自然さを改善し、意味の通る比喩・後悔・実感・文体を保つ。

依頼は全文の自然な推敲とし、見出しと意味を保持、表記や口調の一律統一はしない。
12だけは提供資料に基づく事実の訂正・補足も許可した。執筆役は対象Skill・原文・依頼・
資料だけを読み、本文を返した。モデルと設定は同じセッションの既定を継承した。
本文評価をそろえるため執筆時のCLI実行は許可せず、コードやフックの比較は行っていない。

カタログと推敲手順に「語が一覧にあるだけで直さず、通じる体験の比喩は残す」を明記した。
新しい執筆役で11と未使用の13を生成し直した結果が保存されている。12は初回の出力である。
最終出力だけを示して初回の失敗を成功扱いしない。

評価役は、許可を能力へ変える例と、相手を作り足す例を不合格とする校正課題を先に通過した。
その後、Skill名を隠した本文を固定基準で評価した。11・13の再評価は全基準を満たし、
12も意味・重要情報・修正・声の基準を満たした。呼出元でも原文・資料・出力を読み合わせた。
12に対するCLI差分の追加候補は、提供資料にある内容と照合して採否を判断した。

## 評価の限界

各原稿は一回の生成であり、モデルや再試行をまたぐ安定性、任意の文書での優位性は示さない。
執筆中のCLI操作や検査結果の納品まで検証した評価でもない。候補がないことだけで意味の保持を判定していない。
この生成の後に行ったカタログの分類整理、語彙追加、改稿ガイドの記録手順の簡素化は、
この評価で効果を測った変更には含めない。CLIの形態素ルールは自動テストで別に検証する。

保存された本文のハッシュは`artifacts.sha256`にある。ルートから
`cd eval/revision-quality && shasum -a 256 -c artifacts.sha256`で確認できる。
