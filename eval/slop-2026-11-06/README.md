# 生成文書によるスロップ評価（2026-11-06）

[todesking「スロップ表現100連発」](https://zenn.dev/todesking/articles/5bc43f449ecdf6)の手順にならい、複数のモデルで文書を生成し、別のモデルが不自然な表現を抜き出して、suikoの指摘と本文上の範囲で照合する。これまでの評価標本（`eval/labeled/`）は規則の仕様から実装者が書いた作例で、規則の外へ広がる型を測れなかった。この集合は規則の調整に使っていない文書で、suikoが実際の生成文のスロップをどれだけ拾うかを測る。

## 手順

1. 生成: 同じ12通りの依頼（ジャンル×テーマ×文体の指定）を各モデルに渡す。文体の指定は記事の`metaphor`・`literary`・`subject`・`motto`・`principle`に対応させ、指定なし（plain）を対照に置く。依頼文にスロップやsuikoの語は入れない。
2. 注釈: 生成に使っていないモデルが、記事の基準で不自然な表現を抜き出す。suikoの規則や出力は見せない。
   - 意味破綻型（semantic_breakdown）: 流し読みでは自然に見えるが、精読すると意味が破綻している表現。
   - 過剰圧縮型（over_compression）: 短く言い切ろうとして情報を省きすぎ、内容が一つに定まらない表現。下位分類は「省きすぎ」「動詞の独自用法」「主題と述語の不一致」。
3. 人の確認: 注釈の`review`を`accepted`・`rejected`に変える。`rejected`は集計から外す。未確認（`unreviewed`）のまま集計した値は、注釈モデルの判断に対する一致率である。
4. 照合: `suiko-eval spans eval/slop-2026-11-06/annotations.toml [--experimental]`。注釈の範囲と指摘の範囲が重なれば検出とする。

## LLMによる確認（`suiko meaning`）の評価

決定的な規則では意味破綻型をほとんど拾えなかったため、suikoに任意の`meaning`を加えた（[yomiyasu](https://github.com/nanaism/yomiyasu)と同じく、意味の判定はLLMに任せ、決定的な検査は照合に使う）。依頼文と本文を`claude -p --model sonnet --tools "" --disable-slash-commands`へ渡し、返った抜き出しを本文の範囲へ照合する。返答は`meaning/<版>/<文書id>.txt`に保存し、照合だけを再実行できる。

| 依頼文 | 検出（180文書・注釈50件） | 第3回だけ（7件） | 指摘 | 注釈と重なった割合 | 対照（指定なし10文書）1000字あたり | 人間21文書 |
|---|---|---|---|---|---|---|
| 版1 | 36/50（0.720、0.583〜0.825） | 4/7 | 702 | 5.1% | 1.51 | — |
| 版2 | 13/50（0.260、0.159〜0.396） | 2/7 | 51 | 25.5% | 0.00 | 6件（5文書、1000字あたり0.07） |
| 版2＋既定のlint（読点の2規則を除く） | 17/50（0.340） | — | — | — | — | — |

- 版1は記事の基準と「選ばないもの」を文で伝えるだけの依頼文。版2は[yomiyasuのslop-catalog 8章](https://github.com/nanaism/yomiyasu/blob/main/references/slop-catalog.md)の「残してよい比喩」（読み取れる比喩、後の文で理由を述べる比喩、働きが一読で分かる擬人化）を足し、候補ごとに精読した読み（`reading`）を書かせ、読みを書けた候補をsuikoの側で捨てる。版2は180文書で91件をこの読みで捨てた。
- 人間21文書は、公開の著作権切れの随筆など11本（`eval/corpus`の1万字以下）と、外部の現代の文書10本（note の随筆6、障害報告などの業務文書4）。外部の文書は著作権のため返答をコミットせず、件数だけを記録した。版2の6件は「歴史は常に人間を嗅ぎだしている」（坂口安吾）「大海の波の如くに歩いて行く」など、書き手が選んだ表現で、誤検知と見てよい。
- 版1の返答1件（sonnet-14）は、JSONの文字列に余分な引用符が入って読めず、指摘なしとして数えた。

```sh
cargo +1.97 run --release -- spans eval/slop-2026-11-06/annotations.toml --no-lint --meaning-cache eval/slop-2026-11-06/meaning/claude-sonnet-v2
# キャッシュにない文書だけ実行する
cargo +1.97 run --release -- spans eval/slop-2026-11-06/annotations.toml --no-lint --meaning-cache eval/slop-2026-11-06/meaning/claude-sonnet-v2 -- claude -p --model sonnet --tools "" --disable-slash-commands
```

読み方の注意。

- 注釈もLLM（Opus）で、確認役（Sonnet）と同じ記事の基準を使っている。同じ系統のモデルが同じ基準で判断するので、一致率は人が確かめたスロップへの検出率より高く出やすい。人の確認（`review`）を済ませるまでは、上の検出は注釈モデルとの一致率である。
- 注釈は「迷ったら選ばない」で控えめに付けたため、注釈と重ならない指摘がすべて誤りとは限らない。誤りの目安には、注釈が0件の対照（指定なし）と人間の文書を使った。
- 版2は、版1が対照の自然な文（「空いた床に座って食べた夕飯は、なぜかよく覚えている」）に付けた指摘を見てから作った。注釈の外れた例は見ていないが、対照の値は調整に使った文書での値である。

## 学んだこと

評価を進めるたびに追記する。

### LLMの確認は、拾える量と誤りの少なさの釣り合いを依頼文で決める（2026-11-06）

同じSonnetで、版1は注釈の72%を拾うが指摘の95%が注釈の外で、文体の指定のない自然な文にも付いた。版2は誤りを大きく減らした（対照0件、指摘の25%が注釈と重なる）が、拾えるのは26%に下がった。「確信のあるものだけ」と文で頼むだけでは絞り込めず、候補ごとに読みを書かせて機械的に捨てる手順で初めて絞り込めた。どちらの版を使うかは、見落としと誤指摘のどちらを避けたいかで決まる。suikoの既定は、誤りの少ない版2にした。

### LLMの返答は形式が崩れる（2026-11-06）

180文書の返答で、同じキーの重複（`"pattern"`が2回）、一度出した答えを撤回して二つ目のJSONを出す返答、文字列に余分な引用符が入った返答があった。suikoは、重複したキーを後の値で読み、`items`を持つ最後のJSONを採り、形式の誤った項目だけを捨てる。読めない返答は評価全体を止めず、`unparsed`として件数とidを出す。

### 人の文章の表現も意味が定まらないと判定される（2026-11-06）

版2でも、人間21文書のうち5文書に指摘が付いた。坂口安吾や寺田寅彦の随筆の比喩、noteの随筆の「多くの文字を紙面からぼろぼろこぼしながら」など、書き手が選んだ表現である。意味が一つに定まらないことと、AIらしいことは同じではない。`meaning`の指摘は、書き手が意図した表現かを確かめる候補として扱い、AI判定には使わない。

### 擬人化と意味の破綻は別物（2026-11-06、改修1の後）

第3回の評価用で、既定の擬人化の規則は「椅子が次の客を待つ」「光が待っ」「窓が静かな港のように私たちを待っ」等に5件付いたが、注釈者はどれもスロップとしなかった。注釈の7件はすべて「金魚すくいの袋が……小さな水槽の月のように光っていた」「彼の声には、使われなくなったホームの長さがあった」のような、比喩の写像が精読で成り立たない型で、擬人化の形をしていない。記事の意味破綻型は「物が人の動作をする」ことではなく「精読すると何を指すか定まらない」ことで定義されている。suikoの規則は形（主語の類と動詞）で擬人化を拾うため、筋の通った擬人化に当たり、形を持たない写像の破綻を拾えない。語や動詞を足す改修では、この差は埋まらない。

### スロップの型は依頼ごとに偏る（2026-11-06）

第1回は「物・時間が人の動作をする」型が多く、第3回は「〜のように」の写像の破綻が中心だった。同じ文体の指定でも題材で出る型が変わる。一回分の生成で規則を直すと、次の回の型に外れる。評価用は複数の回にまたがって集める。

### 注釈の件数は回によって大きく変わる（2026-11-06）

同じ注釈モデル・同じ基準で、60文書あたり23件・20件・7件だった。注釈者は第3回で「文脈で補える比喩が多かった」と報告している。1回の件数が少ないと、検出率のWilson区間が広すぎて改修の効果を判定できない（0/7の上限は0.354）。評価用は件数で目標（たとえば50件）を決めて集める。

### 範囲の重なりだけでは検出を過大に数える（2026-11-06）

注釈と指摘の範囲が重なれば検出とすると、第1回の60文書では既定の規則で4/23になる。ただし4件とも「〜は、」の読点の規則で、意味の破綻とは無関係に注釈の範囲へ入っていた。重なりの率は、どの規則が当たったかと併せて読む。`spans`の明細は当たった規則を列に出し、`--ignore`で偶然重なる規則を外した率を出せるようにした。

### 閉じた語彙表の規則は、新しい生成文の破綻へ広がらない（2026-11-06）

意味破綻型33件（120文書）のうち、物・感覚・時間を動作主にする規則（`explanatory_metaphor`・`sensory_role_mismatch`）が拾えたものは0件だった。以下は第1回の例。規則は「動作主の語の表」と「その類が取らない動詞の表」の両方に載った組だけを見るため、片方が外れると拾えない。

- 動作主が表にない: 「湯気だけが、昨日の寒さをそっと包んでいる」（湯気）、「雨音が、店じゅうの本に静かに降り積もっていた」（雨音）、「古本屋は……ひとつの時間を静かに棚へ戻した」（店）
- 動詞が表にない: 「やかんは胸の内に朝を育て始める」（やかんは11月6日に足したが、育てるは表にない）、「時間は……そっと寄り添っている」（寄り添う）

### 過剰圧縮型は文脈で決まる（2026-11-06）
